# Webhost Billing v0.1.0-alpha.1

Release date: 2026-09-30

`v0.1.0-alpha.1` is the first public source prerelease of Webhost Billing. It is
intended for evaluation and development. It is not a statement of production
readiness and carries no compatibility or support guarantee.

## Included scope

- NestJS REST API, Next.js customer/administrator interface, and NestJS/BullMQ
  worker and scheduler applications in one pnpm TypeScript monorepo.
- Customer registration and secure cookie sessions, administrator TOTP support,
  products, orders, invoices, immutable payment history, services, support tickets,
  email queues, renewal automation, audit records, and fake provider adapters.
- PostgreSQL/Prisma persistence, Redis/BullMQ background work, Docker development
  infrastructure, and documented production Compose topology.
- Apache-2.0 project licensing, contribution/security/support policies, CI, CodeQL,
  Dependabot, secret scanning, SBOMs, checksums, and an immutable GitHub Release.

## Install and validate

Requirements are Node.js 24, pnpm 11.22.0, Docker Engine with Compose, PostgreSQL,
and Redis. Use fictional data and fake providers for evaluation.

```sh
git clone --branch v0.1.0-alpha.1 --depth 1 https://github.com/ebit101/webhost-billing.git
cd webhost-billing
corepack enable
corepack prepare pnpm@11.22.0 --activate
pnpm install --frozen-lockfile
cp .env.example .env
docker compose up --detach --wait postgres redis
pnpm db:generate
pnpm db:migrate:deploy
pnpm db:verify
pnpm build
```

Never use the example environment as production configuration and never commit a
populated `.env` file. See `README.md`, `.env.example`, and the documents under
`docs/` before operating the application.

## Database and upgrade notes

This tag contains 21 forward-only Prisma migrations, from the initial schema through
administrator two-factor constraint hardening. A new installation must apply the
complete migration set with `pnpm db:migrate:deploy` before starting application
processes.

There is no earlier supported public tag, so this release defines no supported
in-place upgrade path. Do not down-migrate. Before any later upgrade, create and
verify an encrypted backup; incompatible rollback requires restoring the matching
pre-migration database into an isolated database and deliberately cutting over.

## Configuration notes

- Every workspace package remains `private: true`; this release does not publish npm
  packages.
- External payment, SMTP, cPanel/WHM, and registrar credentials are not included.
- Fake providers are the development and automated-test default.
- The web API origin is compiled into the Next.js image and must match the intended
  deployment origin if an operator later builds containers.
- Exactly one scheduler process is permitted. Permanent hosting termination remains
  administrator-confirmed and is never scheduled automatically.

## Known limitations and safety boundaries

- This is alpha software. Pre-1.0 APIs, configuration, and schemas may change.
- Production readiness is `NO-GO`: production SMTP, off-site recovery ownership,
  monitoring/alert delivery, final business policy, and credentialed provider gates
  remain incomplete or separately controlled.
- Online payment gateways, real email delivery, real hosting-panel actions, DNS
  changes, registrar operations, and production deployment were not authorized by
  this release.
- The source release contains no container images and does not create or update a
  `latest` tag.
- Operators are responsible for infrastructure, secrets, backups, legal compliance,
  provider accounts, and safe upgrade/rollback procedures.

## Artifacts and verification

The GitHub Release includes deterministic Git-generated `.tar.gz` and `.zip` source
archives, complete and production-only CycloneDX JSON SBOMs, and `SHA256SUMS`.

On Unix-like systems:

```sh
sha256sum -c SHA256SUMS
gh release verify v0.1.0-alpha.1 --repo ebit101/webhost-billing
gh release verify-asset v0.1.0-alpha.1 webhost-billing-v0.1.0-alpha.1.tar.gz --repo ebit101/webhost-billing
```

On PowerShell, compare each line in `SHA256SUMS` with `Get-FileHash -Algorithm
SHA256 <file>`. The immutable GitHub Release locks the tag and uploaded assets and
provides a release attestation tying them to the tagged commit.
